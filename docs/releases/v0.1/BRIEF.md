# BRIEF.md — Personal File Manager v0.1

> 문서 위치: `docs/releases/v0.1/BRIEF.md`
> 문서 역할: 무엇을, 왜 만드는가. 제품 개요와 v0.1 범위를 정의한다.
> 후속 문서: `PRD.md` → `SPEC.md` → `PLAN.md` → `backlog.json`

---

## 1. 프로젝트 의도

이 프로젝트의 목적은 범용 File Manager를 만드는 것이 아니다.

> **터미널 CLI 에이전트(claude / codex / agy)로 작업하는 흐름에서, 작업 디렉터리에 도달하고 그 위치에서 도구를 실행하기까지의 마찰을 없애는 것.**

현재 반복되는 마찰은 다음 세 가지다.

1. `cmd`를 실행하고 `cd`로 목표 디렉터리까지 찾아 들어간다.
2. 문서 내용을 확인하려고 VSCode를 새로 띄운다.
3. 제목 한 줄, 몇 줄 추가하는 수정을 위해 무거운 편집기를 연다.

v0.1은 이 세 가지를 없애는 것을 목표로 한다. 파일 복사/이동/이름변경은 이 흐름을 둘러싼 보조 작업이며,
Total Commander의 기능 집합을 복제하는 것은 목표가 아니다.

### 1.1 대표 사용 흐름

```text
앱은 항상 떠 있다
  → 두 패널로 문서 트리를 훑는다
  → F3로 내용을 즉시 확인한다
  → F4로 제목이나 몇 줄을 고치고 저장한다
  → 필요한 디렉터리에서 Ctrl+T로 터미널을 띄우고 claude / codex / agy 를 실행한다
  → 본격적인 코드 작업이 필요하면 그때 Ctrl+E로 VSCode를 연다
  → 정리가 필요하면 F5 / F6 / F2로 파일을 옮기고 이름을 바꾼다
```

### 1.2 설계 성격

- **상주형(resident) 도구다.** 하루에 한 번 실행해 계속 띄워 둔다. 매번 새로 실행하는 앱이 아니다.
- **키보드 우선이다.** 마우스는 보조 수단이며, 모든 핵심 동작에 키가 배정되어야 한다.
- **에이전트와 공존한다.** 앱이 파일을 보는 동안 CLI 에이전트가 같은 파일을 고칠 수 있다. 이 전제가 새로고침과 저장 정책을 결정한다.
- **Total Commander의 손버릇을 계승한다.** F3 보기 / F4 편집 / F5 복사 / F6 이동 / F7 새 폴더 / F8 삭제.

### 1.3 병행 목적

이 프로젝트는 `mdviewer`에 이은 두 번째 Codex 기반 개발 과제이기도 하다.
동일한 기술 스택에서 더 큰 규모의 애플리케이션을 문서 주도(BRIEF → PRD → SPEC → PLAN → backlog)로
구현하는 절차 자체를 검증한다.

## 2. v0.1 우선순위

기능은 의도 기여도 순으로 세 등급으로 나눈다. 구현 순서와 완료 기준이 이 등급을 따른다.

### 2.1 Core — 없으면 앱을 켤 이유가 없는 것

| 항목 | 설명 |
|---|---|
| 듀얼 패널 탐색 | 좌/우 독립 경로, 키보드 이동, Active Pane 개념 |
| 터미널 실행 | 현재 경로를 작업 디렉터리로 하는 터미널 창을 새로 연다 |
| 에이전트 실행 | 같은 방식으로 `claude`, `codex`, `agy` 실행 |
| VSCode 실행 | 현재 경로에서 `code .` |
| F3 뷰어 | 텍스트 / Markdown 읽기 전용 확인 |
| F4 내장 편집 | 앱 안에서 간단 수정 후 저장 |
| F5 / F6 | 복사 / 이동 |
| F2 | 이름 변경 |
| 즐겨찾기 · 경로 복원 | 자주 가는 경로로 즉시 점프, 마지막 좌우 경로 복원 |
| 새로고침 | Ctrl+R 및 창 포커스 복귀 시 자동 갱신 |

**즐겨찾기와 경로 복원이 Core인 이유**: 매번 루트부터 방향키로 내려가야 한다면
`cd`의 마찰을 앱 내부의 탐색 마찰로 옮긴 것에 지나지 않는다.

**새로고침이 Core인 이유**: 에이전트가 터미널에서 파일을 생성·삭제하는 동안
패널은 낡은 상태로 남는다. 이 앱 고유의 사용 패턴에서 상시 발생한다.

### 2.2 Support — 있어야 실제로 쓸 수 있는 것

| 항목 | 설명 |
|---|---|
| Space 다중 선택 | 연속 선택 후 일괄 작업 |
| F7 / F8 | 새 폴더 / 삭제(휴지통) |
| 정렬 | 이름 / 확장자 / 크기 / 날짜, 오름·내림 |
| 좌우 패널 교환 | 전체 탐색 상태 교환 |
| 상태바 | 파일·폴더 개수, 선택 개수와 용량 |
| Dark 테마 | 기본 테마 |
| 이름 충돌 처리 | 덮어쓰기 / 건너뛰기 / 자동 이름변경 / 취소 |
| 진행·취소 | 대용량 작업 중 상태 표시와 중단 |

### 2.3 Peripheral — v0.1에 넣되 마지막에 구현

| 항목 | 설명 |
|---|---|
| 드라이브 용량 표시 | `사용 가능 / 전체` |
| 파일 아이콘 | 시스템 아이콘 사용 |
| Light 테마 | Dark의 대응 테마 |
| 마우스 조작 | 클릭 선택, 더블클릭 열기 |

## 3. 화면 구성

```text
┌──────────────────────────┬──────────────────────────┐
│ Drive [Free / Total]     │ Drive [Free / Total]     │
│ Current Path             │ Current Path             │
├──────────────────────────┼──────────────────────────┤
│ Name  Ext  Size  Date    │ Name  Ext  Size  Date    │
│ [..]                     │ [..]                     │
│ ...                      │ ...                      │
│                          │                          │
├──────────────────────────┼──────────────────────────┤
│ Files / Dirs / Selected  │ Files / Dirs / Selected  │
└──────────────────────────┴──────────────────────────┘
  ActivePanePath >  [ Command Launcher ]
  F2 Rename  F3 View  F4 Edit  F5 Copy  F6 Move  F7 New  F8 Delete
```

- 두 패널은 동일한 구조와 기능을 가진다.
- 하나는 항상 Active Pane이며 시각적으로 명확히 구분된다.
- 모든 파일 작업의 Source는 Active Pane, 기본 Destination은 반대쪽 패널의 현재 경로다.

### 3.1 패널 상단

- 현재 드라이브와 여유/전체 용량: `D: [109.3 G / 236.7 G]`
- 현재 전체 경로: `D:\projects\nampluskr\10_active\project-a`

### 3.2 파일 목록 컬럼

`파일명` / `확장자` / `크기` / `날짜`

- 폴더를 파일보다 먼저 표시한다.
- 최상단에 상위 디렉터리 항목 `[..]`을 둔다.
- `[..]`은 선택 대상에서 제외한다.
- Focus(커서 위치)와 Selection(선택 상태)을 시각적으로 구분한다.

### 3.3 상태바

Total Commander의 `선택분 / 전체` 병기 형식을 따른다.

```text
용량: 128.4 M / 934.6 M    파일: 5 / 51    폴더: 2 / 4
```

- 선택 항목에 폴더가 포함되어도 하위 용량을 재귀 계산하지 않는다.
- 폴더는 개수에만 반영하고 용량 합계에서 제외한다.

### 3.4 하단 공통 영역

- Active Pane의 현재 경로
- Command Launcher 입력 영역
- Function Key 안내

## 5. Command Launcher

이 앱의 존재 이유에 해당하는 기능이다.

### 5.1 동작 모델

> **현재 Active Pane의 경로를 작업 디렉터리로 하는 터미널 창을 새로 띄우고, 앱은 관여를 끝낸다.**

`claude`, `codex`, `agy`는 대화형 TUI다. 앱 내부에 출력을 표시하려는 시도는 하지 않는다.
따라서 stdout 캡처, 진행 상태 추적, 내장 터미널 에뮬레이터는 모두 범위 밖이다.

### 5.2 기본 프리셋

| 프리셋 | 실행 형태 |
|---|---|
| `cmd` | 현재 경로에서 터미널 창 |
| `claude` | 터미널 창에서 `claude` 실행 |
| `codex` | 터미널 창에서 `codex` 실행 |
| `agy` | 터미널 창에서 `agy` 실행 |
| `code .` | 터미널 없이 VSCode 직접 실행 |

앞의 넷은 동일한 동작이며 실행할 명령만 다르다. 실질적으로 두 종류의 동작뿐이다.

### 5.3 자유 명령 입력

v0.1에서는 **임의 명령 문자열 입력을 지원하지 않는다.**

- 프리셋 실행과 터미널 열기로 필요한 기능이 모두 충족된다.
- 자유 입력이 필요하면 터미널을 연 뒤 그 안에서 입력하면 된다.
- 명령 주입 위험을 원천 차단한다.

### 5.4 실패 처리

대상 프로그램이 설치되어 있지 않거나 실행할 수 없으면 오류를 명확히 표시한다.
오류를 숨기거나 조용히 무시하지 않는다.

## 6. 뷰어와 편집기

### 6.1 F3 — 뷰어 (읽기 전용)

- Markdown: 렌더링해서 표시. 렌더링 실패 시 원문 표시.
- 그 외 텍스트: 원문 표시.
- 대상: `.md` `.txt` `.log` `.json` `.yaml` `.yml` `.toml` `.ini` `.csv` 및 일반 소스 코드
- 이미지 / PDF / 동영상 뷰어는 v0.1 범위 밖이다.

### 6.2 F4 — 내장 편집기

기본 편집기는 외부 Notepad가 아니라 **앱 내장 경량 편집기**다.

외부 편집기를 띄우면 창 전환, 저장, 창 닫기, 목록 갱신의 마찰이 그대로 남는다.
"제목 바꾸기, 몇 줄 추가"라는 목적에는 문법 강조도 자동완성도 필요 없다.

- 원문 텍스트를 그대로 편집한다.
- `Ctrl+S` 저장, `Esc` 닫기. 저장하지 않고 닫으려 하면 확인한다.
- 큰 파일은 편집 모드 진입을 막는다. 그런 파일은 VSCode에서 연다.
- 본격적인 편집이 필요하면 `Shift+F4`로 VSCode에 넘긴다.

### 6.3 편집 시 지켜야 할 것

파일을 쓰는 기능이므로 다음 세 가지가 반드시 필요하다.

| 항목 | 이유 |
|---|---|
| 원본 인코딩 유지 | 한글 Windows의 `.txt` `.log` `.ini`는 CP949인 경우가 흔하다. UTF-8로 덮어쓰면 기존 한글이 깨진다 |
| 원본 줄바꿈 유지 | CRLF를 LF로 바꿔 저장하면 Git diff가 파일 전체로 잡힌다 |
| 저장 전 변경 감지 | 열어둔 사이 CLI 에이전트가 같은 파일을 고쳤을 수 있다. 덮어쓰기 전에 확인한다 |

세 번째는 이 앱 고유의 위험이다. 앱에서 파일을 열어둔 채 터미널에서 에이전트를 돌리는 것이
기본 사용 패턴이기 때문이다.

## 7. 파일 작업 원칙

### 7.1 대상 결정

```text
Source      = Active Pane의 선택 항목
              선택이 없으면 포커스 항목 하나
Destination = 반대쪽 패널의 현재 경로
```

작업 실행 전에 Source와 Destination을 사용자가 확인할 수 있어야 한다.

### 7.2 이름 충돌

같은 이름이 존재하면 임의로 덮어쓰지 않는다. 다음 선택지를 제공한다.

- 덮어쓰기
- 건너뛰기
- 자동 이름 변경
- 취소
- **모두 적용** 체크 — 없으면 50개 파일에 50번 대화상자가 뜬다

폴더 대 폴더 충돌 시 기본 동작은 **병합**이다. 폴더 통째 대체는 기존 내용을 소실시키므로 기본값이 아니다.

### 7.3 삭제

- `F8` / `Delete`는 **휴지통**으로 보낸다. 영구 삭제가 기본이면 사고가 난다.
- `Shift+Delete`가 영구 삭제이며, 별도 확인을 거친다.
- 여러 항목이 선택되어 있으면 전체가 대상이다.

### 7.4 실패 처리

- 부분 실패를 허용한다. 10개 중 3개가 실패해도 나머지 7개는 진행하고, 결과를 요약해 보여준다.
- 사용 중인 파일, 권한 없음, 경로 없음 등의 오류를 숨기지 않는다.
- 작업 완료 후 관련 패널의 목록과 상태바를 갱신한다.
- 가능한 범위에서 작업 전 포커스 위치를 유지한다.

### 7.5 진행과 취소

파일 작업 Queue나 Background Job Manager는 만들지 않는다.
다만 다음 셋은 대용량 작업에서 필수이며, 별도 프레임워크 없이 구현 가능하다.

- 작업 중임을 알리는 표시 (현재 처리 중인 파일명 정도)
- 취소 수단
- 완료 후 성공/실패 요약

이것이 없으면 대용량 복사 중 창이 멈춘 것처럼 보이고, 사용자는 강제 종료한다.
그 시점의 파일 시스템 상태는 보장되지 않는다.

---

## 8. 상태 유지

### 8.1 실행 중 유지 (패널별 독립)

- 드라이브, 현재 경로
- 포커스 위치, 선택 항목
- 스크롤 위치
- 정렬 기준과 방향

좌우 패널 교환 시 위 상태 전체가 함께 이동한다. 표시 문자열만 바꾸지 않는다.

### 8.2 종료 후 복원

- 마지막 좌우 패널 경로
- 마지막 선택 테마
- 창 크기와 위치
- 즐겨찾기 목록

즐겨찾기는 v0.1에서 전용 편집 UI를 만들지 않는다. 설정 파일 직접 편집으로 충분하다.

## 9. UI 스타일

- VS Code 계열의 조밀한 개발자 도구 스타일.
- 정보 밀도를 높이고 여백과 장식을 최소화한다.
- 애니메이션을 사용하지 않는다.
- Active Pane / 포커스 항목 / 선택 항목을 명확히 구분한다.
- 키 입력에 대한 시각적 반응이 즉시 나타나야 한다.

### 9.1 글꼴

- 일반 UI: `Segoe UI`
- 경로, Command Launcher, 뷰어/편집기 본문: `Cascadia Code`, fallback `Consolas`

### 9.2 테마

- Dark 기본, Light 제공.
- 색상은 컴포넌트에 하드코딩하지 않고 공통 토큰으로 관리한다.
- 사용자 정의 테마 편집기는 v0.1 범위 밖이다.

## 12. v0.1 완료 기준

happy path만이 아니라 실패 경로를 포함한다. 아래 항목은 모두 실제로 검증되어야 한다.

### 12.1 의도 검증 (최우선)

- [ ] 앱을 띄운 상태에서, 임의의 프로젝트 디렉터리에 도달해 터미널을 여는 데까지 키 입력 5회 이내로 가능하다.
- [ ] 즐겨찾기 키 한 번으로 자주 쓰는 경로에 도달한다.
- [ ] 현재 경로에서 `claude` / `codex` / `agy` / `cmd`가 터미널 창으로 실행된다.
- [ ] 앱을 종료해도 실행된 터미널 세션이 살아 있다.
- [ ] 현재 경로에서 `code .`이 실행된다.
- [ ] Markdown 파일을 F3로 렌더링해 확인한다.
- [ ] F4로 문서를 수정하고 저장한다. 인코딩과 줄바꿈이 원본과 동일하게 유지된다.
- [ ] 편집 중 외부에서 같은 파일이 변경되면 저장 시 경고가 뜬다.
- [ ] 터미널에서 파일을 만든 뒤 앱 창으로 돌아오면 목록이 자동 갱신된다.
- [ ] 재시작 시 마지막 좌우 경로와 테마가 복원된다.

### 12.2 파일 작업 — 정상 경로

- [ ] Tab으로 Active Pane을 전환한다.
- [ ] Space로 여러 항목을 연속 선택하고 상태바가 즉시 갱신된다.
- [ ] F5 복사 / F6 이동이 좌우 패널 사이에서 동작한다.
- [ ] F2 이름 변경, F7 새 폴더가 동작한다.
- [ ] F8이 휴지통으로 보낸다. 휴지통에서 복원 가능하다.
- [ ] 다중 선택 항목에 대해 복사/이동/삭제가 일괄 동작한다.
- [ ] Ctrl+U로 좌우 패널의 경로·포커스·선택·스크롤·정렬이 통째로 교환된다.
- [ ] 정렬 기준과 방향을 바꿀 수 있다.

### 12.3 파일 작업 — 실패 경로

- [ ] 같은 이름이 존재할 때 선택지가 제시되고, "모두 적용"이 동작한다.
- [ ] `D:` → `C:` 등 드라이브 간 이동이 정상 동작한다.
- [ ] 사용 중인 파일이 포함되어도 나머지 항목의 작업이 계속되고, 실패 목록이 표시된다.
- [ ] 권한 없는 디렉터리 진입 시 앱이 죽지 않고 오류를 표시한다.
- [ ] 대용량 폴더 복사 중 진행 표시가 보이고 취소할 수 있다.

### 12.4 성능

- [ ] 5,000개 이상 항목이 있는 디렉터리(예: `node_modules`)를 열어도 방향키 이동이 끊기지 않는다.
- [ ] 드라이브 용량 조회가 파일 목록 표시를 지연시키지 않는다.
- [ ] 연결 끊긴 네트워크 드라이브가 있어도 앱 시작이 블로킹되지 않는다.
- [ ] Space 다중 선택 시 파일 시스템을 재조회하지 않는다.

### 12.5 UI

- [ ] Dark / Light 테마를 전환할 수 있고 마지막 선택이 저장된다.
- [ ] 지정된 키 매핑이 4장 표대로 동작한다.
- [ ] 하단 Function Key 안내가 표시된다.
