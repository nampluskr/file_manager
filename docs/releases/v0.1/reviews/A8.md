## Major

### 1. 드라이브 프로브 타임아웃이 호출자만 제한하고 파일시스템 기아(starvation)는 막지 못함

`drives.ts`(23행)는 반환된 Promise를 1.5초 후 타임아웃시키지만, 내부 `statfs()` 호출은 계속 libuv 워커를 점유한다. 24개 프로브가 동시에 실행되는 반면 `main/index.ts`(16행)는 워커를 16개만 설정한다. 환경변수 적용이 충분히 이르다고 가정해도, 16개의 연결 불가 드라이브가 워커 풀 전체를 점유해 `listDirectory()` 같은 무관한 파일시스템 작업이 Windows SMB 타임아웃까지 지연될 수 있다.

재현: 연결 끊긴 매핑 드라이브를 16개 이상 구성하고 앱을 실행한 뒤 즉시 디렉터리 목록을 요청한다. 드라이브 목록은 논리적으로 약 1.5초 후 완료되지만, 무관한 파일시스템 호출은 훨씬 오래 지연될 수 있다.

위반 조항: §10.3 Non-blocking Queries, §10.4 Drive Enumeration ("열거 완료 전에도 UI가 정상 동작해야 함").

### 2. `sys:fileIcon`이 경로 순회(path traversal) 및 임의 파일 생성을 허용

`ipc/index.ts`(362행)는 확장자가 문자열인지만 검사한다. `icons.ts`(32행)는 이 값을 그대로 경로에 결합하고 `a` 모드로 파일을 연다.

재현:
```ts
window.fileManager.fileIcon('x\\..\\..\\outside.tmp')
```
`join(probeDir, 'probe.x\\..\\..\\outside.tmp')`가 전용 프로브 디렉터리 밖으로 정규화된다. 결과 상위 경로가 존재하고 쓰기 가능하면 `open(..., 'a')`가 해당 파일을 생성하거나 갱신한다. 고유한 확장자 문자열은 영구 캐시를 무한정 늘리고 프로브 파일을 무제한 생성할 수도 있다.

확장자 입력은 구분자, 순회 세그먼트, NUL, 유효하지 않은 파일명 문자, 과도한 길이, IPC 계약과 맞지 않는 선행 점(dot) 등을 거부해야 한다.

위반 조항: §12.3 IPC Validation, §10.5 Other Rules.

### 3. 포커스가 `[..]`에 있어도 선택된 파일이 계속 조작 대상이 됨

`FilePane.tsx`의 `getOperationTargets()`(29행)는 포커스된 항목이 `[..]`인지 확인하기 전에 선택된 항목을 먼저 반환한다.

재현:
1. 파일 하나 이상을 선택한다.
2. 선택을 해제하지 않고 키보드 포커스를 `[..]`로 이동한다.
3. F5, F6, F8, Shift+Delete 중 하나를 누른다.
4. 선택된 파일이 여전히 작업 대상이 된다.

영구 삭제의 경우 특히 위험하다. SPEC은 포커스 항목이 `[..]`일 때 어떤 작업도 실행되지 않아야 한다고 규정한다.

위반 조항: §5.3 Operation Target.

### 4. 다른 창의 드라이브 메뉴가 열려도 활성 창의 키 입력이 억제되지 않음

각 창은 `FilePane.tsx`(179행)에서 자체 window 레벨 드라이브 메뉴 리스너를 설치하지만, 메뉴를 소유한 창만 자신의 창 레벨 키 핸들러에서 `driveMenuOpen`을 인지한다.

재현:
1. 오른쪽 창을 활성화한다.
2. Alt+F1로 왼쪽 창의 드라이브 메뉴를 연다.
3. ArrowDown 또는 Enter를 누른다.

왼쪽 메뉴가 키를 처리하지만, `preventDefault()`는 전파(propagation)를 막지 못하므로 오른쪽 창의 핸들러도 포커스를 이동하거나 포커스된 항목을 활성화할 수 있다. 결과적으로 Enter가 왼쪽 창에서 드라이브를 선택하는 동시에 오른쪽 창에서 파일/디렉터리를 열 수 있다.

위반 조항: §4.7 Drive Selection, §16.7 Key Routing.

### 5. 설정 쓰기 경합, 명시적 종료 시 저장을 대기하지 않음

렌더러 설정은 `App.tsx`(45행)에서 300ms 타이머 후 저장된다. 별개로 창을 닫으면 `main/index.ts`(155행)에서 read-modify-write 방식의 bounds 갱신이 시작된다.

이 두 개의 전체 스냅샷 쓰기는 직렬화되지 않는다. 나중에 쓴 쪽이 오래된 경로, 테마, 정렬, bounds를 복원할 수 있다. 두 호출이 같은 밀리초에 발생하면 `settings.ts`(110행)가 같은 임시 파일명을 생성할 수도 있다.

트레이 종료는 더 심각하다. 닫기 핸들러가 `persistWindowBounds()`를 await 없이 시작하고 종료가 계속 진행된다. `writeFile()`/`rename()` 완료 전에 프로세스가 종료될 수 있다.

재현: 테마나 경로를 변경한 직후 창을 닫거나 트레이 Quit을 선택한다(느리거나 이동식 디스크에서 더 잘 재현됨). 재시작 후 오래된 설정, 누락된 bounds, 또는 저장 실패를 관찰한다.

위반 조항: §2.2 Window Lifecycle, §13.3 Settings Rules.

### 6. 드라이브 용량 응답이 오래된 데이터로 현재 드라이브를 덮어쓸 수 있음

`FilePane.tsx`의 `refreshDriveUsage()`(134행)에는 요청 ID나 드라이브 문자 검증이 없다.

재현:
1. 느린 드라이브 D:로 이동한다.
2. 빠르게 C:로 이동한다.
3. C: 요청이 먼저 완료되고 D: 요청이 나중에 완료되도록 둔다.

늦게 도착한 D: 응답이 C:의 표시된 용량을 덮어쓴다. 늦은 거부(rejection) 역시 더 최신의 성공 결과를 지울 수 있다.

위반 조항: §3.2 DriveBar, §10.3 Non-blocking Queries.

### 7. 필수 전역 단축키가 조용히 사용 불가능해질 수 있음

`main/index.ts`(173행)의 `globalShortcut.register()`는 반환값을 확인한다. 그러나 실패 시 `console.error()`만 출력한다. 패키징된 사용자에게는 표시되는 경고, 대체 단축키, 재시도 경로, 트레이 표시가 전혀 없다.

재현: 다른 애플리케이션이 설정된 단축키를 먼저 등록한 상태에서 이 앱을 실행한다. 창은 정상 동작하지만, 필수 표시/숨김 단축키는 사용자에게 설명 없이 영구적으로 작동하지 않는다.

위반 조항: §16.6 Global, §19.1 Required Configuration.

### 8. Shift-클릭의 anchor가 내비게이션·정렬 후에도 오래된 인덱스로 남음

`useFilePane.ts`의 `rangeAnchorRef`(97행)는 배열 인덱스를 저장하며 내비게이션, 새로고침, 정렬 이후 재설정되거나 변환되지 않는다.

재현:
1. 큰 목록의 하단 근처 항목을 클릭한다.
2. 다른 디렉터리로 이동하거나 정렬을 변경한다.
3. 다른 항목을 Shift-클릭한다.
4. 선택이 이전에 클릭한 항목이나 현재 포커스가 아니라 오래된 숫자 인덱스부터 시작한다.

내비게이션 후 경로 변경으로 선택이 초기화되었음에도, 임의의 큰 범위가 선택될 수 있다. 이렇게 의도치 않게 선택된 항목들이 파괴적 작업의 대상이 될 수 있다.

위반 조항: §5.1–§5.2 Selection Model and Rules.

## Minor

### 9. 오버레이 색상이 테마 토큰 계약을 우회함

`styles.css`(33행) 및 작업 오버레이는 하드코딩된 `rgb(0 0 0 / 45%)`를 사용한다. `--selected-item` 토큰도 정의되어 있지만 사용되지 않는다.

제공된 팔레트에서 명확한 Light 테마 텍스트 대비 실패는 발견하지 못했으나, 이러한 하드코딩된 스크림(scrim)은 컴포넌트 색상이 테마 변수에서 와야 한다는 요구사항을 위반한다.

위반 조항: §14.3 Theme Tokens.

## Codex가 확인(문제 없음)한 항목

- 두 번째 인스턴스 실행 시 이미 생성되어 숨겨진 창을 `main/index.ts`(130행)에서 올바르게 복원, 표시, 포커스한다.
- 포터블 설정은 §13.1이 요구하는 대로 정확히 `app.getPath('userData')/settings.json`으로 해석된다. 동일 Windows 프로필 내에서 포터블 실행 파일 폴더를 이동해도 설정을 잃지 않는다.
- 두 아이콘 캐시 모두 확장자를 소문자로 변환하며, 빈 확장자도 공유 캐시 키로 취급한다. `.PNG`, `.png`, 확장자 없는 파일 모두 행(row)마다 IPC 호출을 유발하지 않는다. 캐시된 실패도 `cache.has()` 확인으로 반복 호출을 피한다.
- `FileRow`는 원시(primitive) prop만 받으며 `React.memo`로 감싸져 있고, 이벤트 위임이 행 메모이제이션 규칙을 유지한다.
- 창을 숨겨도 반복 폴링 타이머는 남지 않는다. 단발성 설정/타이프어헤드 타이머, 진행 중 쿼리, 시작 시 드라이브 프로브, 활성 파일 작업은 계속될 수 있으며, 문제가 되는 경우는 위 Major 항목에서 다뤘다.
- `sys:listDrives`는 요청 페이로드가 없어 검증 대상이 아니다. `sys:driveUsage`는 형태와 대소문자를 검증하지만, §10.4가 열거 범위를 C:–Z:로 정의함에도 A:/B:를 허용해 불필요한 레거시 드라이브 프로브를 허용한다(경미한 사항으로 별도 등급 부여 없이 보고됨).
