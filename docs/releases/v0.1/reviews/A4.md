## Resolved findings

1. Major — Relative paths passed `resolve()` and were therefore accepted as absolute paths. Resolved by rejecting non-absolute input before resolution in `assertAbsolutePath`.
2. Major — CP949 used separate read and write codec implementations. Resolved by using `iconv-lite` `cp949` in both directions with byte-for-byte read validation and character-for-character write validation.

## Remaining finding

1. Minor — `writeTextFile.ts` retains a narrow TOCTOU window between its final mtime/hash comparison and `rename()`. Reproduction requires an external write after the final comparison completes and immediately before the next synchronous `rename()` call. Node's standard filesystem API provides no atomic compare-and-rename primitive or portable advisory lock for this operation. The implementation performs both an initial and immediately pre-rename version check, writes to a temporary file, and atomically replaces only after those checks. This residual window is accepted as a documented Minor limitation for v0.1.
